Build a complete full-stack web application called:

PREDICTIVE MAINTENANCE
"Identify Machine Health States using Machine Learning + RAG"

The application must include BOTH frontend and backend and must be fully functional.

==================================================
1. CORE PROBLEM
==================================================

Problem Statement:

"Predictive Maintenance – Identify machine health states."

The application should accept a machine/industrial sensor dataset uploaded by the user, especially datasets downloaded from Kaggle.

The system should analyze sensor and operational data and classify the health condition of a machine.

Possible health states can include:

- Healthy
- Normal
- Warning
- At Risk
- Critical
- Failure

IMPORTANT:

Do NOT hardcode these classes if the uploaded dataset already contains a target/health-state column.

The system should inspect the uploaded dataset and identify:

- Numerical columns
- Categorical columns
- Possible target column
- Missing values
- Duplicate records
- Sensor features
- Machine-related features
- Class distribution

If the target column cannot be detected automatically, allow the user to select it manually.

==================================================
2. MACHINE LEARNING + RAG
==================================================

The project MUST use both Machine Learning and RAG.

They must have separate responsibilities.

MACHINE LEARNING:

The ML model performs the actual machine-health classification.

Pipeline:

Dataset
↓
Data Validation
↓
Preprocessing
↓
Feature Engineering
↓
Train/Test Split
↓
Multiple Classification Algorithms
↓
Model Evaluation
↓
Best Validated Model
↓
Machine Health Prediction

Recommended algorithms:

1. Random Forest
2. Logistic Regression
3. Decision Tree
4. K-Nearest Neighbors
5. Gradient Boosting / XGBoost if available

Compare models using:

- Accuracy
- Precision
- Recall
- F1 Score
- Confusion Matrix

Show the performance of every model.

Do not simply hide the comparison.

==================================================
3. RAG SYSTEM
==================================================

Implement a Retrieval-Augmented Generation system.

RAG should NOT perform the machine-health classification.

RAG is responsible for:

- Explaining machine health states
- Retrieving maintenance knowledge
- Explaining sensor conditions
- Explaining possible causes
- Providing maintenance recommendations
- Answering questions about machine health
- Providing contextual information based on retrieved documents

Knowledge base should contain information about:

- Predictive maintenance
- Preventive maintenance
- Machine condition monitoring
- Vibration analysis
- Temperature monitoring
- Pressure monitoring
- Motor health
- Bearing failure
- Lubrication problems
- Overheating
- Mechanical wear
- Electrical faults
- Sensor anomalies
- Equipment failure
- Maintenance strategies
- Industrial condition monitoring

RAG pipeline:

Maintenance Documents
↓
Text Chunking
↓
Embeddings
↓
Vector Database
↓
Retriever
↓
Relevant Context
↓
LLM
↓
Maintenance Explanation

Use a maintainable vector database such as:

- ChromaDB
OR
- PostgreSQL + pgvector

Choose the option that is easiest and most reliable in Replit.
